# D7 installed beta acceptance

## Evidence and remaining work

Desktop CI already builds Windows x64 and Ubuntu 24.04 packages and exercises
the renderer and the staged native binaries. D7 adds smoke tests for the
installed EXE and DEB on disposable runners. The tests install, run against a
loopback MQTT peer using an isolated profile, and uninstall. The new steps
require a CI run on the pushed commit. An Ubuntu runner under Xvfb does not
establish native Ubuntu Desktop acceptance.

Use the [beta user guide](USER_GUIDE.md) for installation, operation, updates
and rollback. Retain both package versions and a synthetic portable project for
the acceptance run.

## Native desktop acceptance

Run this sequence on Windows 11 x64 and Ubuntu Desktop 24.04 LTS x64. Repeat
on Ubuntu Desktop 26.04 LTS before claiming verification on that version.

1. Install the earlier package. On Windows check German and English setup,
   both installation scopes and a dedicated non-default folder. Confirm the
   UAC prompt on the all-users path. On Ubuntu check menu launch and keyring
   access in a signed-in desktop session.
2. Save a synthetic project containing a system and a disabled draft. Create
   a portable backup, close the app, relaunch it and reopen the saved file.
3. Update using the newer package. Reopen the project and compare its draft
   contents and system IDs against the pre-update backup. Check the selected
   app language and protected credentials where supported. Restart the OS and
   repeat the launch and open checks.
4. Follow the rollback procedure with the retained package. Verify that the
   pre-update backup opens and retains its draft and system bindings.
5. Uninstall. Confirm that the executable, application menu entry and package
   registration are removed and that the saved project and backup still exist.
   Reinstall and reopen the retained project.
6. Record the OS version, package versions, checks performed and failures for
   each platform. Use synthetic data and an isolated peer. Live extension
   installation and real device commands require separate authorization.

Publication and signing require a separate request.
